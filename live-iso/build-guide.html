How the custom RPM-builder Live ISO works

A Linux-newbie-friendly guide to the build mechanism, the failures we hit, the engineering lessons, and how the finished Live environment can now burn ISO images to DVD.

2. Core concepts

Live ISO

A filesystem/image that can boot a complete Linux environment without first installing it onto the machine's main disk.

KIWI NG

An operating-system image builder. It reads an image description, resolves packages, creates a root filesystem tree, and packages that tree as an ISO or another image format.

Docker container

The CentOS container is the factory where KIWI runs. It is not converted into the final ISO. KIWI independently assembles the Live OS.

GitHub Actions runner

A temporary Ubuntu VM provided by GitHub. It checks out the repo, runs the build, and disappears after the job; therefore outputs must be uploaded as artifacts.

Mental model:
GitHub runner = rented workshop
CentOS container = controlled workbench
KIWI = image-building machine
CentOS KIWI recipe = blueprint
RPM repositories = parts warehouse
packages.txt = extra parts list
ISO = finished product

3. Final architecture

GitHub Actions (Ubuntu 24.04) │ ├── checks out our repository │ ├── live-iso/build.sh │ └── live-iso/packages.txt │ ├── clones CentOS AltImages c10s recipe │ └── starts privileged CentOS Stream 10 container │ ├── installs KIWI ├── reads packages.txt ├── turns each line into --add-package=... └── builds MIN-Live │ ▼ bootable ISO │ ┌───────────┴───────────┐ ▼ ▼ SHA256SUMS UPSTREAM_COMMIT.txt

The important design choice is that we do not edit CentOS's KIWI XML. We use KIWI's supported package-override interface.

4. Build pipeline

  1. GitHub allocates an Ubuntu 24.04 runner.
  2. actions/checkout checks out this repository.
  3. The workflow deletes large preinstalled SDK directories to free disk space.
  4. bash ./live-iso/build.sh runs the image build.
  5. The script clones the CentOS Alternative Images KIWI descriptions on branch c10s.
  6. The exact upstream Git commit SHA is written to UPSTREAM_COMMIT.txt.
  7. A privileged CentOS Stream 10 container starts, with the recipe, output directory, package list, and /dev mounted into it.
  8. KIWI and build dependencies are installed in that disposable container.
  9. Every package name in packages.txt becomes a KIWI --add-package=... argument.
  10. KIWI builds the official MIN-Live profile plus our packages.
  11. The script creates a SHA-256 checksum.
  12. GitHub uploads the ISO/checksum/upstream revision as a workflow artifact.

Why bash ./live-iso/build.sh?

Calling Bash explicitly does not require the script file itself to have the Unix executable permission bit. This fixed our first CI failure.

Why --privileged and /dev?

Low-level image creation may use loop devices, mounts, and other kernel/device facilities. The container therefore needs much broader access than a normal application container.

5. How KIWI adds our packages

The package list is deliberately simple:

# live-iso/packages.txt
rpm-build
rpmdevtools
...
xorriso

build.sh reads the nonblank, noncomment lines into a Bash array:

mapfile -t packages < <(
  grep -Ev "^[[:space:]]*(#|$)" /packages.txt
)

package_args=()
for package in "${packages[@]}"; do
  package_args+=(--add-package="${package}")
done

The resulting KIWI invocation is conceptually:

kiwi-ng   --type=iso   --profile=MIN-Live   system build   --description=/kiwi   --target-dir=/out   --add-package=rpm-build   --add-package=rpmdevtools   ...   --add-package=xorriso
Why this is better than XML rewriting: it says exactly what we mean: “build the official image, plus these packages.” It is much less coupled to CentOS's internal recipe layout.

6. GitHub Actions concepts

Runner disk space

OS-image builds need significantly more temporary storage than the final ISO because KIWI downloads packages and constructs an entire future root filesystem before compressing it.

sudo rm -rf /usr/local/lib/android /opt/ghc /usr/share/dotnet
df -h

Artifacts

The runner is temporary. The workflow therefore uploads:

live-iso/out/*.iso
live-iso/out/SHA256SUMS
live-iso/out/UPSTREAM_COMMIT.txt

A GitHub Actions artifact is simply a preserved bundle of files produced by the job.

7. What the failures taught us

1. Permission denied

The script lacked the executable bit. Fix: invoke it through bash. Lesson: a shebang does not override Unix file permissions.

2. Wrong upstream repository assumption

We initially used a migration target whose contents did not match the live-image recipe expected by the documentation. Lesson: follow the authoritative build documentation, especially during repository migrations.

3. Shallow clone failed

fatal: dumb http transport does not support shallow capabilities

The Pagure Git endpoint did not support --depth 1. Lesson: Git servers/transports expose different protocol capabilities.

4. Profile/XML assumptions failed

We tried to discover profiles and later tried to inject XML before </image>. The upstream recipe had a different/componentized structure. Lesson: don't build against undocumented internal representation when the tool exposes a supported CLI.

5. Final robust approach

Use repeated --add-package options. This is the clean public interface and survives upstream XML refactoring much better.

The KIWI package manifest

KIWI emits a *.packages file containing the package set actually present in the image. Both the ordinary CI build and tagged release workflow now preserve that file alongside the ISO.

CentOS-Stream-Image.x86_64-10.iso
CentOS-Stream-Image.x86_64-10.packages
SHA256SUMS
UPSTREAM_COMMIT.txt

This is much stronger than guessing from the upstream profile: for any particular build, the manifest is the authoritative answer to “what packages are inside this ISO?”

8. Burn an ISO to DVD

The Live image now includes xorriso, so it can write an existing ISO to a CD/DVD/BD writer.

Step 1 — identify the optical writer

lsblk
xorriso -devices

The first optical drive commonly appears as /dev/sr0, but always verify it rather than assuming.

Step 2 — burn the ISO

sudo xorriso -as cdrecord   -v   dev=/dev/sr0   blank=as_needed   -eject   /path/to/image.iso
OptionMeaning
-as cdrecordUse xorriso's compatibility mode for traditional cdrecord-style commands.
-vVerbose progress/diagnostic output.
dev=/dev/sr0Select the optical writer.
blank=as_neededBlank rewritable media if required; do nothing unnecessary for blank write-once media.
-ejectEject the disc when writing finishes.
/path/to/image.isoThe source ISO to write.
Check the device name carefully. Optical drives are usually /dev/sr*. SSDs/USB disks often appear as /dev/sd* or /dev/nvme*. Do not accidentally point a destructive command at a storage disk.

Where should the source ISO live?

A Live OS often uses RAM or a temporary overlay for writable files. A multi-gigabyte DVD image is better kept on a mounted USB SSD, internal disk, or network share:

Live USB │ ▼ CentOS Stream 10 Live ├── xorriso ├── /dev/sr0 ─────────────► DVD writer └── /mnt/source/image.iso ▲ │ USB SSD / disk / network storage

DVD-R / DVD+R vs DVD-RW / DVD+RW

MediaBehavior
DVD-R / DVD+RWrite-once media; normally cannot be erased and reused.
DVD-RW / DVD+RWRewritable media; can be erased/reformatted and reused.

Why a Live OS can burn discs

The read-only nature of the Live image only describes how the operating-system filesystem is supplied. The DVD writer is a separate hardware device exposed by the Linux kernel. As long as the kernel recognizes the drive and the process has permission to access it, DVD burning works normally.

How xorriso gets into the image

# packages.txt
xorriso

# becomes
--add-package=xorriso

KIWI installs it directly into the Live root filesystem during image construction.

Kernel-module build support

The Live image also installs kernel-devel. This matters when a hardware/vendor installer needs to compile a kernel module locally rather than shipping a module that already matches the running kernel.

running kernel │ │ uname -r ▼ 6.12.x-...el10.x86_64 │ ▼ /lib/modules/<same-version>/build │ ▼ kernel-devel files │ ▼ vendor/module source ──► make ──► .ko kernel module
Related package: CentOS Stream 10 also publishes kernel-devel-matched, whose purpose is to pull matching kernel-core and kernel-devel versions together. The project currently adds the explicitly requested kernel-devel package.

Legacy vendor-installer compatibility

The image also includes chkconfig. Modern CentOS uses systemd, so normal service management should use:

systemctl enable SERVICE
systemctl start SERVICE
systemctl status SERVICE

Some older vendor installers still execute commands such as chkconfig --add ... to register a service. If chkconfig is missing, the installer may abort or leave the service setup incomplete.

Important: installing chkconfig only helps when the installer actually depends on it. If the machine hangs during reboot because of a bad kernel module, shutdown hook, storage/network driver, or another kernel-level problem, chkconfig will not fix that underlying issue.

9. Security, trust, and reproducibility

Checksums

sha256sum -- *.iso > SHA256SUMS
sha256sum -c SHA256SUMS

A checksum detects corruption or modification. It does not by itself prove who produced the ISO; for authenticity, sign the checksum or release artifact.

Privileged build containers

--privileged weakens container isolation. It is acceptable here because the GitHub-hosted runner is ephemeral, but the build code should still be treated as trusted code.

Repeatable vs reproducible

Repeatable: the workflow can build again.
Traceable: we record the upstream recipe commit.
Reproducible: identical inputs yield byte-identical output. That is stronger and may require pinning repository snapshots, package versions, image digests, and timestamps.

10. Linux-newbie glossary

RPM

An installable software package format used by Fedora/RHEL/CentOS-family systems. It contains files plus metadata and dependency information.

DNF / YUM

The package-management layer that resolves dependencies and downloads RPMs from configured repositories.

EPEL

Extra Packages for Enterprise Linux, a repository providing additional software not shipped in the main enterprise-Linux repositories.

CRB

A repository containing many development-oriented dependencies used for software building and some EPEL packages.

chkconfig

A legacy SysV-service compatibility utility. CentOS Stream 10 normally uses systemd and systemctl, but some vendor or driver installers still call chkconfig while registering startup services. Having it installed can prevent those legacy installers from failing, but it is not itself a reboot command or a general fix for reboot hangs.

kernel-devel

The CentOS package containing kernel headers, Makefiles, generated configuration, and other files needed to compile external kernel modules for a particular kernel version. Vendor driver installers commonly look for a path such as /lib/modules/$(uname -r)/build, which is supplied by the matching kernel-devel package.

/dev/sr0

A common Linux device node for the first optical CD/DVD/BD drive. The exact number can vary.

xorriso

A command-line tool for creating, inspecting, manipulating, and writing ISO 9660 optical-disc images.

Bind mount

A way to expose a host directory/file at a path inside a container, such as mapping the upstream recipe to /kiwi and build outputs to /out.

Git branch vs commit

A branch such as c10s is a moving reference. A commit SHA names one exact immutable snapshot. The build follows the branch but records the actual commit used.

Artifact

A file produced by CI/CD, such as an ISO, executable, archive, report, or checksum file.
